## 完成后的用户过程

收到资料或Fish自主使用官方联网 → 分类保存并建立统一资源关联 → 客户端/私聊/群聊使用同一Fish记忆能力按问题检索 → 返回带来源内容 → 主人在客户端查看原件/记忆并更正 → 后续召回采用更正；语义不可用时继续FTS5词法并显示原因。本批群端只读或临时根验收。

## 本票范围与交接

- **先行收拢：** 先以现有原件、资料块和记忆实现接同一资源关联与检索接口，再补资料向量通路及来源／更正；退出互不相认的重复登记和截断检索。

## 完成标准（Acceptance criteria）

- [ ] 长问句首尾和较老资料可参与检索，不因最新候选或前几个词永久漏掉。
- [ ] 更正影响后续召回，来源类别和原文可定位，资料不只停在存档。
- [ ] 仅真实用语义的请求显示混合；不可用继续词法并显示原因，未完成的语义范围单列。
- [ ] 同一资源再保存关联版本，官方查询/正文有来源与取得时间，分类目录正确。

## 替换与删除

### 2026-10-25 已确定目标：统一记忆与一个整理程序

按权威规格4.4、7.6细化，同一后端能力由09-06/09-07管理界面消费，不在页面复制。

- [ ] 客户端、QQ私聊和群聊使用同一Fish记忆读写/检索/修订/整理；人物、场所、时间、原话、消息和文件位置保留来源，退出旧按场所隔离的查询、写入与工具文案，不能只放开保存。
- [ ] 检索→概述→细化沿同一资料及修订展开，具体事件/原话/附件可定位；不建三套互相复制的物理记忆库。
- [ ] 采用SQLite官方FTS5并接入真实词法查询、更新/更正/删除后的索引维护；FTS5不冒充内容归纳或语义检索，原有语义就绪/降级要求保留。
- [ ] 建成一个完整整理程序：取新增或指定范围→基础格式/明确重复项/来源处理→使用Fish配置模型提炼事实、事件与概述→保存及修订→更新FTS5及适用向量索引→返回范围、保存结果和失败内容。未变化内容略过。
- [ ] 每日定时任务与Fish主动整理工具启动同一程序；工具接受范围/引用等必要参数并返回实际执行结果或进度。Fish不逐项操作数据库和索引，不要求每轮主动整理，不为此修改人格。
- [ ] 工具说明只写用途、参数、用法和结果含义；整理能力不增加“什么时候必须记”的提示词。默认北京时间；原件物理删除/归档期限另按确定策略，不自动执行旧90天等建议。
- [ ] 收拢后退出原重复整理、索引更新和场所读取限制；新旧实现不同时修改同一记忆或创建重复整理任务。压缩归01、启动计划接06、界面归09-06，均复用本程序。
