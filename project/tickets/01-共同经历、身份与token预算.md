## 完成后的用户过程

客户端或 QQ 收到消息 → 归一人物、场所、引用和附件关联 → 同一主执行取得本轮材料 → 结果及投递状态回到共同经历；客户端沿现有对话入口可查看对应记录，私聊能接续相关既有材料。群场景只读或临时根模拟。

- **交接约定：** 给后续票提供标准事件引用、稳定主人身份、材料覆盖范围和同一请求组装入口。01 使用仍可用的现有记忆／工具调用位置，不等待 02／04 的新能力，避免形成循环依赖。

## 完成标准（Acceptance criteria）

- [ ] 输入可追溯人物、引用、附件和Fish发言/投递结果；私聊可接续已有跨场所材料。
- [ ] 预算使用当前提供商/模型真实W，初始8%；L1当前原文>L2跨场所原文>L3日小结>L4记忆/资料>L5周月，从最低层裁，原记录不丢；同一配置解析用于请求、保留和压缩触发。
- [ ] 按需取材、不为填满上限补历史；私聊逐请求及整轮实际用量与预算上限分开报告，保留固定开销、各层前后用量和裁剪层，不恢复条数上限。
- [ ] 接收与生成分离，只有主人明确说停才取消，五个时间点可记录；排队不设秒数目标。

## 替换与删除

### 2026-10-25 已确定目标：共同接收、合并与结构改造

需求及验收以权威规格4.3、4.6、4.10.1、7.6为准。本节记录本票责任，不用旧源码决定目标；具体Interface、状态归属和迁移位置在后续codebase-design扫描中落定。

- [ ] 被@、QQ私聊和客户端消息在主思考空闲时第一时间处理；普通群消息先收录，达到8条或45分钟触发，特殊3秒唤醒归06；不把所有来源第一条消息都立即开启主思考。
- [ ] 思考期间持续接收并统一合并后续消息，按到达顺序接续；不为每条消息建独立等待生成回合，不因主人身份插队或调整回复顺序。人物、场所、引用与发送目标保持对应。
- [ ] 思考开始清零群消息计数，期间新消息继续累计；思考完成向06交完成事件以重启45分钟计时，完成时不再清掉期间计数。
- [ ] 与08交接连续3秒文件批次，保留文件各自来源与状态；批次不产生第二个并发主思考，普通文字不增加每句3秒延迟。
- [ ] 结构按最终目标整理：共同接收、材料组装、处理进度各有唯一归属，旧入口迁接后退出；新旧实现不同时写同一进度或重复处理。依本票已有DSH算法要求完成压缩，前端消费结果而不重建算法。

程序运行细节不在本次另行开测；整体完成后沿既定一次体验观察，群只读/临时根。新要求尚未实现，不按历史状态勾选。
