## 完成后的用户过程

客户端选择／导入大附件 → 分块或流式落盘 → 复用 04 的统一资源引用 → 私聊通过 02 的工具按需取前后相关片段 → 客户端可打开原件并区分保存、解析和本轮取用范围；大文件不整份塞进模型请求。

## 本票范围与交接

- **先行收拢：** 先接附件内容通路和统一资源登记，再替换前端、本地入口及存储的重复 20 MiB 检查与整份大 base64 控制请求；保留各层真实协议含义。
- **对应界面：** 文件选择／上传、当前实际限制来源、导入结果和原件访问在本票完成；后端支持而前端仍写死 20 MiB 不算本票交付。
- **交接约定：** 给 07 提供实际大小、资源引用、处理／取用范围和结果；1 GiB 旧订阅参数不转成全局承诺，工作根搬迁不进入本票。

## 已确定的实施约定

**2026-10-25 codebase-design交接：** [文件批次Interface](https://github.com/3259980040-droid/fish-agent/blob/codex/fish-tickets-20261025/project/spec.md#agent-structure-20261025)与[附件/媒体源码映射](https://github.com/3259980040-droid/fish-agent/blob/codex/fish-tickets-20261025/project/implementation-map.md#codebase-design-20261025)已完成。experience拥有连续3秒批次，knowledge拥有原件/下载/解析；同一批次交主执行准备材料，不另建附件库或并发回合。此设计不是已实施的代码。

- 按权威规格4.8新增连续3秒文件接收批次：同批统一处理，后续进入下一批；不改成醒来后只收一次三秒，不因新文件延长本批，不新增同一发送人才可同批的条件。
- 批次保留每个文件的发送者、场所、时间、引用和顺序，登记/下载完成/可解析/本轮读取状态分别如实表达；三秒不代表下载和理解时限。批次交01/主执行接续，不开启并发主思考，普通文字不每句等三秒。与06的自唤醒3秒参数分开，不相互覆盖。
- 按规格 §4.8 分开记录事件、HTTP／工作台控制消息、原件导入、QQ 实际连接、视觉协议与模型 token 窗口的配置；实施对照表填写旧值、新值、作用层和真实生效来源。前端读取对应实际值，不各自写死一份。
- 大原件沿附件内容通路分块／流式落盘并返回稳定资源引用；普通控制动作和会话事件不内联整份大 base64，模型按需要取片段／视图。复用现有工具、资源与投递接口，不建第二套附件库。
- 区分已保存、已解析／索引范围和本轮实际读取范围；后续片段仍能从原件取得，不能将只索引开头说成全文已理解。不支持的格式、真实外部通道限制和失败原因据实返回，未完成不伪装成功。
- 每次模型请求继续走 01 的统一 token 组装：预算是上限，实际用量单列，大附件不自动变成整份模型输入。

按[权威规格 §4.10](https://github.com/3259980040-droid/fish-agent/blob/codex/fish-tickets-20261025/project/spec.md#deep-module-interfaces)与[实施对照表：模块接口映射](https://github.com/3259980040-droid/fish-agent/blob/codex/fish-tickets-20261025/project/implementation-map.md#module-interface-map)实施。原件交资源模块登记，入口只交内容流／引用，主执行按需取用；成果和失败状态沿已有客户端／投递接口返回。

## 完成标准（Acceptance criteria）

- [ ] 客户端与后端配置含义一致，列出各层当前／实施后值；20 MiB 旧附件限制、28 MiB base64 判断、32／2 MiB HTTP 控制限制和 1 GiB 旧订阅值逐项说明去向，不全局粗放放大。
- [ ] 最终同一次体验中，从客户端导入一份大于旧 20 MiB 限制的文本原件；原件完整保留，取得稳定资源引用，私聊能按需要读取其前后相关片段。
- [ ] 原件大小、解析／索引范围和本轮实际取用范围可查看；模型请求不内联完整大文件，仍记录实际输入用量与预算上限。
- [ ] 结果或文件可从客户端打开；如经 QQ 私聊交付则保留真实结果，不把上传排队当送达。实际未覆盖的文件大小、格式或通道明确列为未验证。

## 替换与删除

退出前端／本地入口／附件存储重复硬编码 20 MiB、用普通工作台 JSON 整份搬运大附件的路径，以及只取开头却无法按需访问后段的旧取用方式；真正仍需的各层协议限制保留其职责并显示来源。

旧 DSH 订阅退出时一起清理其失效配置；仍使用的订阅不得因本票直接停用。保留原件、已有关联和可用索引，不物理删除文件，不把根迁移混入本票。
