# 05：原图、局部视觉与图片表情取用

**What to build:** 主人发来图片后，Fish 可以取得真实原图及必要局部，客户端能对应原件和分析视图。
**Status:** ready-for-human
**执行状态：** 源码已实现、已构建部署；集中私聊已有实发证据，覆盖范围与未完成项见实施记录/07-集中验收/最终交付.md，等待主人最终体验验收。

## 完成后的用户过程

私聊或客户端收到图片 → 关联原件 → 本轮整体查看或按问题取得局部／长图片段 → 图像与必要文字实际进入请求 → 回复可追溯所见范围；如取用表情，保留原 GIF 并沿主人私聊通道交付。

## 本票范围与交接

- **先行收拢：** 先核媒体准备、图像输入和专业候选核对的真实调用职责，再接原图／局部视图；保留必要子模块，只退出已被替代的重复最终判断。
- **对应界面：** 本票让聊天中的原图、分析视图、读取状态和结果关联可用；不能只产出缓存描述或后台文件。
- **交接约定：** 向主执行提供资源模块的图像视图结果及来源，图像实际送入、读取成功与识别是否正确分别记录；07 关联其真实过程。

## 已确定的实施约定

规格4.5、4.9。先在对照表核媒体准备、图像输入、专业候选和最终回复的调用关系，再迁或退重复职责；原件和派生视图使用04的统一资源关联。

### 模块接口落点

按[权威规格 §4.10](https://github.com/3259980040-droid/fish-agent/blob/codex/fish-tickets-20261025/project/spec.md#deep-module-interfaces)与[实施对照表：模块接口映射](https://github.com/3259980040-droid/fish-agent/blob/codex/fish-tickets-20261025/project/implementation-map.md#module-interface-map)实施。取原图、局部和动图原件归资源视图接口；保留媒体准备与专业核对的必要职责，不增加第二个最终识别决定。 本段不新增需求或独立验收批次。

## 完成标准（Acceptance criteria）

- [ ] 模型实际收到正确原图/局部与必要文字，文件名或缓存描述不冒充新图输入。
- [ ] 局部问题可取得可核对细节，主题仅辅助候选，来源和更正可关联。
- [ ] 原GIF不被分析视图覆盖，若本次发出只发主人私聊。
- [ ] 媒体可追踪、读取成功、模型展示和识别结果分别记录，未改善例据实列明。

## 替换与删除

核职责后退出重复视觉判断和被替代的单一缩图调用，保留媒体解码及确有用途的候选核对；不凭两个文件就整份删。
