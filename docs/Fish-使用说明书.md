# DSH + Fish 使用说明

更新：2026-10-20。本说明按当前实际运行的 E 盘版本编写。

## 打开和日常使用

双击桌面的 **DeepSeek Harness**。客户端内保留原 DSH 工作会话，侧栏的 **Fish** 打开社交与远程工作面板；切换页面不会清空 DSH 会话。原独立 Fish 快捷方式已归档，正式入口只有这一处。

主人 QQ 为 **3259980040**，机器人为 **1417334937**。当前主人私聊已接通，默认处于**聊天模式**；群 1043230169 的监听、自动回复均关闭。

在与大肥鱼的私聊发送以下整条命令即可切换：

| 操作 | 发送内容 | 实际变化 |
|---|---|---|
| 聊天 | `/聊天模式` 或 `切换聊天模式` | 使用社交人格、历史和聊天工具 |
| 干活 | `/工作模式` 或 `切换工作模式` | 同一会话启用 DSH 本机文件、终端等工作工具 |
| 来回切换 | `切换模式` | 在聊天与工作之间切换 |

模式是程序保存的状态。切换保留原会话、人物关系、人格和历史；无需把“你是主人”反复写进提示词。权限按实际 QQ 账号核验，普通群友说自己是主人不会得到同样的电脑操作权限。

工作模式可直接交办：“在工作目录写一篇文章，保存为 Word，完成后把文件发给我”；后续可以要求修改同一文件。当前默认工作目录：

`E:\Program Files\DSH\source\fish\qq-work\owner-files`

这是真实电脑操作环境，能使用已安装的程序和工具；遇到需要登录或本机未安装的软件，会返回实际失败或缺少的条件。

## Fish 的七个页面

| 页面 | 用途 |
|---|---|
| 对话 | 在客户端与 DeepSeek 聊天、选择会话、切换聊天/工作模式、上传附件、查看任务状态及继续历史 |
| 性格 | 导入、编辑、保存、选择和应用人格；兼容 Markdown 与已适配的社区项目字段 |
| 记忆 | 搜索、查看和更正长期事实，查看语义检索与日周维护状态 |
| 表达库 | 查看候选/已启用/已停用的黑话、称谓和表达，核对来源原话，保存主人纠正 |
| 任务 | 查看、创建、修改、取消持久化定时任务及执行记录 |
| 频道 | 查看真实连接状态、主人账号、群监听和回复开关 |
| 设置 | 权限、工作目录、每日限制、外发开关、关闭后后台运行、空间发布、重载后台 |

设置当前为**每日无上限**。这关闭的是 Fish 本地每日调用拦截；供应商额度、网络故障和接口限流仍会按真实错误显示。

“关闭窗口后保持后台运行”当前开启。关闭客户端后，QQ 私聊和定时任务继续运行；可在设置中调整。“重载 Fish 后台”重启后台服务，会中断正在执行的本地聊天任务，历史仍保留，可继续交办。

## 人格、窗口和回复

人格是表达方式，窗口保存当前话题和临时情境。普通更换/重新加载人格保留已有历史和主人长期事实；要体验独立历史，另建窗口。主人事实记忆不会默认按每个人格复制一整套；独立测试窗口与正常长期记忆的写入范围分开。

“这轮当串子”这类要求作为本轮上下文持续，直至你更改或结束；聊天/工作模式切换不会另外新建一个无历史的回复代理。

常规回复目标为 **20–500 字**，按问题分配长度；短梗可以更短。括号动作仅在有助于表达时使用。模型仍可能啰嗦或没接住梗，可以直接纠正，也可以在表达库保存有来源的说法。入库、检索到、模型实际采用是不同阶段；当前“实际采用”未被完整追踪时显示“未知”。

DSH 的项目规则与工具说明在工作模式加载。聊天模式使用社交配置，收到的文档按材料处理，不因其中写着命令就自动成为主人指令。模型能否生成某类内容仍受实际供应商模型行为影响。

## 记忆和自动整理

当前采用 **SQLite + 中文嵌入模型 bge-small-zh-v1.5 + FAISS**，同时按关键词和语义检索。SQLite 保存事实、来源、状态和更正历史；向量索引是可重建的检索数据。当前运行状态为 `ready / hybrid`，待补建向量为 0。

明确要求“记住……”可即时保存；更正后保留旧值历史，以新事实生效。提取与自动学习按来源和范围执行，临时角色设定不会默认固化为永久事实。相关记忆按当前问题召回，随后进入本轮上下文，不是把所有历史全塞给模型。

| 整理 | 时间/方式 | 做什么 |
|---|---|---|
| 日整理 | 每天 04:00，Asia/Shanghai | 增量读取新的主人/本地用户消息，提取可用事实；每来源单次最多处理 120 条，游标保留余下内容 |
| 周维护 | 每周日 04:30 | 合并重复、整理自动事实的过期与活跃状态；人工保存/确认的事实不随自动衰减改写 |
| 停机恢复 | 后台恢复后 | 按保存游标补做遗漏窗口，已完成窗口不重复整理 |
| 向量补建 | 本地后台 | 给新增/更正事实生成索引；模型不可用时保留关键词检索，恢复后补建 |

没有新消息的日整理不会调用模型，不会自动向 QQ 发日报。日周整理不是唯一保存时机，也不代替当前对话历史。

长会话仍使用 DSH 原生上下文压缩，保留任务与摘要；长期记忆和上下文压缩各自承担不同用途。传输上限不是模型上下文容量：本地运行时消息连接默认可接收 **1 GiB**，不能据此推断模型一次能读取 1 GiB 文本。

## 文件、联网、表情和真实发送

- 客户端附件支持图片、DOCX、PDF 和常见文本；本地上传每个最多 **20 MiB**、一次最多 **3 个**。原文件按会话归档，提取文本进入索引。超大或不支持的内容会说明原因，已归档不代表已解析。
- 图片读取和发送是分别实现的能力。表情库已有真实发送链路；主人私聊发收藏表情已实际成功。
- 工作模式可以用真实文件工具读写电脑文件，使用 `file_send` 通过 QQ 上传文件，返回上传回执；文字路径不算已交付文件。
- 搜索/网页读取已接入实际工具；网页端 DeepSeek 的联网按钮不会自动赋予 API 联网能力。这里由 Fish/DSH 工具完成，模型依据工具返回内容作答。
- 文档接收归档后保留来源；音视频仅归档或使用实际已接入的解析能力，不把文件存在说成已经理解。

实际验证过：机器人发送收藏表情；在电脑生成和修改文件；上传 TXT、DOCX 文件到主人 QQ；客户端读取 DOCX 和图片；真实搜索与网页正文读取。

## 定时、主动消息和外发规则

可以在主人私聊要求：“20 分钟后回复我……”“明天上午 9 点提醒我……”“每天晚上 8 点……”。时间按 **Asia/Shanghai** 解释。任务保存到 DSH 原生调度记录，可在 Fish 的任务页查看、修改和取消。电脑需开机，QQ/NapCat 与后台需可用。

一次性提醒停机后补发一次；周期任务合并遗漏，不补发一串过期消息。发送记录区分成功、失败和结果未知，结果未知不盲目重发。后台重载与客户端重开保留任务和已完成发送记录。

当前外发设置：主人正常私聊回复允许，主人创建的定时结果允许；明确交办的群发送另有开关，并受白名单限制。群自动参与由频道页的监听/回复开关控制，当前关闭。并未开放陌生人私聊或批量群发。

本轮实际测试由主人 QQ 发起：“发送迁移后验收文件，并在 20 秒后回复我”。文件卡片已到达，机器人随后实际发出 **“迁移后定时联调完成”**。

## QQ 空间动态

已接入当前 NapCat 支持的草稿和发布接口，可保存正文、图片和可见范围。先生成草稿得到编号，再发布指定草稿；设置中的“空间发布”开关当前关闭。

当前已核对协议版本及空间登录凭据可用，**没有进行真实动态发布测试**，没有生成任何“发布成功”的假回执。这里不等同于完整的 QQ 空间管理器；查看、评论、点赞等未接入能力不在本次承诺内。需要定时发布时可由工作任务调用已接入发布动作，仍以实际接口回执为准。

## 数据、备份和目录

正式根目录是 `E:\Program Files\DSH`，运行时的数据权威位置如下。保留工程内部约定结构，避免把运行依赖按文件扩展名拆散。

```text
E:\Program Files\DSH\
├─ source\
│  ├─ dsh\                         DSH 客户端和原生扩展源码
│  │  └─ apps\desktop\.desktop-build\development\
│  │     ├─ home\                  原 DSH 会话、配置与调度数据
│  │     └─ electron-user-data\     客户端用户数据
│  └─ fish\                        Fish 业务、渠道、工具和源码
│     ├─ data\                    QQ记录、记忆、表达库、附件、任务和状态
│     ├─ homes\                   QQ/research 原生运行配置
│     ├─ qq-work\owner-files\     默认电脑任务工作目录
│     ├─ outputs\                 按任务分类的产物、动态草稿、验收结果
│     ├─ backups\                 本项目恢复副本与自动记忆备份
│     ├─ vendor\runtime\          Node、记忆专用 Python 等必要依赖
│     └─ 需要清理\过期自动备份\   超出近期保留份数的旧自动备份
├─ runtime\python313\             项目专用基础 Python
├─ backups\migration\             迁移记录、入口备份和历史验收资料
├─ 需要清理\                      已停用旧副本，按来源与用途分类
└─ 使用说明.md
```

原始聊天、长期记忆、有效附件继续保存。本轮只清理可再生成的过期网页缓存和旧完成任务快照，不按年龄盲目删除聊天媒体。自动记忆备份每日最多一次，近期保留 14 份，更多旧备份移入 Fish 内的“需要清理”，由你决定删除。

自动记忆备份包含 QQ 记忆、群语言库、人物库，不是整个电脑的备份。迁移恢复副本另外保留完整工程与原始数据。本机各分区属于同一物理磁盘，这些副本用于误改恢复，不能抵御整块硬盘损坏。

旧文件去向见 [清理清单](<E:/Program Files/DSH/需要清理/清理清单.md>)。**F 盘旧兼容入口仍需保留**，不能和“需要清理”里的旧副本一起删除。归档在同一分区不释放空间，手动删除对应副本后才释放。

## 出问题时先看哪里

1. Fish → 频道，查看主人消息处理、原生环境、工具记忆是否连接。
2. Fish → 设置，核对暂停、模式、工作目录、每日无上限及发送开关。
3. 正在执行的任务先在任务/对话页看真实状态；无活动任务时可用“重载 Fish 后台”。
4. 启动日志在 `source\fish\data\system\logs`。分享日志前遮去连接凭据，不要直接公开整个用户配置目录。

本轮解决的是工具、数据、发送、客户端与目录的完整运行链路。拟人化、接梗和幽默效果仍需用你自己的聊天标准继续评估，不能由工具联调成功推断已经达到网图效果。
