# ADR 0002：一个宿主管理独立Fish实例

- 状态：已采纳，按2026-10-26唯一规格§8与九张工单逐步接通。
- 背景：裸root同时被当成源码、凭据和Agent数据根；前端历史会话不等于独立实例。切换页面不应改变后台归属。
- 决定：使用InstanceContext明确host_root、instance_id、directory。稳定初始实例main承接原有资料，数据同级排放于data/instances；端口、连接、凭据、MCP应用继续共享，现有数据库/压缩/整理算法继续复用。旧路径调用者显式改用project_path，不修改Path行为，不复制程序，不双写。
- 迁接：首次新版本初始化只移动可变资料；迁接记录先写完整意图，再同盘rename；只更新配置和数据库内结构化路径引用，不改原话/ID/删除状态和附件原件。qq-work/AGENTS.md等源码模板保留宿主；integration启动参数保留宿主，qzone实例选项单独读取。当前阶段临时根核对，生产仅最终停服部署时执行。
- 接口：instances.list列真实身份；每次窗口工作台及工具请求带instance_id。当前W01提供初始路径，W02增加创建/启停与并行常驻，R03提供实例有效工具能力，W03接QQ参与分发，W04接真实回合工作台。未指定ID只沿稳定main接续旧调用者，不保存全局最后选中窗口。
- 主执行：每实例一个消费者，共用实现；同实例按原始顺序认领材料，普通思考可静默，明确提醒保留独立履约。R01负责认领修正，R02负责计时/真实执行状态和退出强制请求调试副本。
- R01认领：有触发资格的输入按原到达顺序交接，仅合并相邻的普通同场所材料；独立计划实例各自保留原委托与结果。未满8条且无@的群材料仍按原触发规则等待，不阻塞已触发的客户端/私聊。认领事务固定引用，背景和同批晚到文件可见不代表其消息已处理；只有本轮认领范围和本轮自身事件写入已考虑。文件继续按3秒窗口整批读取，晚到消息的新文本仍有下一轮机会。原turn_view返回有序材料及原件引用，合并回合的trace取实际当前材料。
- 执行结果接续：计划是触发原因，后续自主回合按计划目标还原场所；全部思考沿原结束钩子重新等待45分钟。QQ结果监听固定发起实例和执行引用，技术错误沿原管理员记录读取。正常请求及工具接续直接记录原trace/usage/材料边界，额外请求预览仅保留按需诊断入口与历史。
- 边界：同QQ账号同群允许多个实例独立参与，目录/进度/工具值不能互相覆写。未来新增能力可插件化，当前不拆散既有基础。M01跨盘源码迁移和B3研究凭据处置仍延期。

- W02生命周期：窗口启用的唯一持久来源是本实例Governance.paused_roles.qq；catalog只记稳定ID/名称，不再保存另一份running开关。enabled为保存值，running为真实消费者状态。每实例Runtime拥有主消费者、计时和停止Event，原计划检测调度、每日整理/embedding维护迁到该生命周期；宿主ResearchWorker、registry和服务器仍只有一份。停止中的旧消费者退出前不生成第二份，宿主维护循环据实际保存值接续。
- W02人格：新窗口只接受主人明确手写或指定来源实例+revision的预设。未配置时真实暂停、当前人格为空，不从宿主默认人格隐式借用；改名不改ID，切换不执行启停。工具资源及主人授权沿现有资源承接，实例设置分别保存。
- 整理：同一实例的每日、工具和客户端继续提交原memory_curate_runs；接收时固定截止与原库高水位，learning_jobs保存逐来源完成事实。程序自动接续正常批次，仅本范围无剩余后更新小结和完成状态；失败或暂停留原执行引用与未完成来源，恢复跳过已完成项。新来源留下一范围，模型只提炼内容，不决定下一批或游标。

- 资料读取：knowledge.search/open、原fish_doc_search/read与工作台资料检索/原件打开固定读取调用实例的原库；场所scope保留为来源，不再默认限制为owner或当前群。doc_store显式scope仍可筛选来源，None读取该物理实例全部来源的当前修订。旧别名只在本实例原别名表解析，同名跨来源歧义要求使用检索返回的真实资料编号。
