# ADR 0003：每实例持续接续真实模型会话

- 状态：按主人 2026-10-26 对跨回合缓存改造的授权实施。
- 原因：每次从 QQ/客户端业务记录重建 messages，会改写模型已经见过的消息形式，丢失实际 assistant、reasoning_content 和工具调用/结果；调整材料位置不能消除这类跨回合缓存损失。
- 决定：主执行在现有 experience.db 的 agent_state 使用 model_context:<role> 保存当前模型协议投影，不创建第二个聊天库。首次采用现有材料；之后只追加新原件、内容/投递状态更正、发生变化的参考材料和本轮输入。原件成为“已考虑”或转入回查不算新内容。每实例独立，主模型路由改变重新从原资料建立，实际人格/表达修改更新唯一系统头。
- 执行：只有持真实 execution 引用、非 child 的主执行使用此投影；人格预览、研究与旧转接调用不写进它。实际 API 消息、完整 provider reasoning 和工具协议保留；重载仍可接续。历史数据不会被程序重新执行，工具仍按当前实例、会话和实时开关执行。
- 压缩：采用现行 ContextBudget 的真实模型窗口、触发/保留比例，复用 compaction 的完整范围选择、摘要说明、context_checkpoints 和 chat_catalog。摘要和模型投影在同库事务提交，失败不推进。该主执行退出旧的 per-store 自动压缩入队，避免同一压力触发双份付费摘要；原始档案的手动/旧任务入口仍可处理未建立模型会话的实例。现有 context.compact 对已建立投影的实例压缩实际模型会话。
- 原件：源库、原消息处理顺序、认领和投递不变。模型图片字节放入现有 media/model-context 的内容寻址文件，SQLite 只存引用，读取时还原原 URI。压缩不删除原始资料；关键词再次命中同一原件不会把刚压缩的范围重新塞回，模型主动调用历史查询工具时仍追加真实回查结果。
- 删除：删除客户端原件同时使有关运行投影失效；AgentState 的比较提交防止尚未结束的旧 writer 把它写回来。它不撤销主人身份、工具权限或实例开关。
- 观测：原 context_requests 继续统计真实调用，主回合附带实际 epoch/checkpoint，压缩调用归原 trace 记账。只把前缀不变作为程序验收，实际命中率以新的 API 回执为准，不用增长无用提示或额外热身抬高数字。
